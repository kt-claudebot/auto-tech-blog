UUID（Universally Unique IDentifier）の仕様は RFC 9562（2024年5月、K. Davis / B. Peabody / P. Leach、Proposed Standard）で定義され、RFC 4122 を置き換えました。以下は RFC の要約を元にした整理です（ページ全体の約8割を読んだ範囲に基づきます）。正確な文言や細部は原文を参照してください。

## テキスト形式

UUID は 16 オクテット（128 ビット）で、ハイフン区切りの 5 グループ（4・2・2・2・6 オクテット、いわゆる 8-4-4-4-12）の 16 進数で表記します。大文字・小文字は区別されません。RFC の例は次のとおりです。

```
f81d4fae-7dec-11d0-a765-00a0c91e6bf6
```

## バージョンとバリアントのビット

- バリアント: オクテット 8 の上位ビット。本仕様では bit 64, 65 が `1`, `0`（2進で `10xx`）。
- バージョン: オクテット 6 の上位 4 ビット（bit 48〜51）。

## 各バージョンの特徴

| バージョン | 概要 |
| --- | --- |
| v1 (`0001`) | 時刻ベース。60 ビットのタイムスタンプ（1582年10月15日からの 100 ナノ秒単位）、14 ビットのクロックシーケンス、48 ビットのノード ID（MAC アドレス由来またはランダム）。 |
| v4 (`0100`) | 乱数ベース。128 ビット中 122 ビットがランダムで、残り 6 ビットがバージョンとバリアント。 |
| v6 (`0110`) | v1 の並べ替え版。タイムスタンプを上位ビット側から格納し、データベースのインデックス局所性を改善。v1 互換が不要なら v7 が推奨されています。 |
| v7 (`0111`) | 時刻順。上位 48 ビットが Unix エポックからのミリ秒タイムスタンプ。残り 74 ビット（バージョン／バリアント除く）はランダムですが、単調増加カウンタ等に使う実装もあり得ます。 |
| v8 (`1000`) | 実験・ベンダー独自用。バージョンとバリアント以外の 122 ビットは実装依存で、一意性は仕様では保証されません。 |

## Nil UUID と Max UUID

- Nil UUID: 全 128 ビットが 0 — `00000000-0000-0000-0000-000000000000`
- Max UUID: 全 128 ビットが 1 — `FFFFFFFF-FFFF-FFFF-FFFF-FFFFFFFFFFFF`

## 選び方の目安

上記の RFC の記述から言えるのは、ランダム性だけが必要なら v4、データベースのキーなどで時刻順に並べたいなら（v1 互換が不要な限り）v7 が候補になる、という点です。これは RFC の記述を踏まえた筆者の解釈であり、採用前に各言語・DB の対応状況を確認してください。
