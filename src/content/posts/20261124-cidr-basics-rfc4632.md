CIDR（Classless Inter-domain Routing）は、IPv4 アドレスの割り当てと経路集約の方式を定めた仕組みです。RFC 4632（2006年8月、V. Fuller / T. Li、BCP 122、RFC 1519 を置き換え）の内容のうち、実務でよく使う部分を整理します。以下は RFC の要約を元にしており、正確な文言は原文を参照してください。

## CIDR の目的

RFC によると、32ビットの IPv4 アドレス空間を節約し、グローバルな経路情報の増大を抑えることが目的です。

## プレフィックス表記

プレフィックスは「4オクテットのアドレス + `/` + 0〜32 の10進数」で書きます。スラッシュの後ろの数字は、先頭から何ビットがネットワーク部かを表します。RFC の例は次のとおりです。

- 旧クラス B の `172.16.0.0` → `172.16.0.0/16`
- 旧クラス C の `192.168.99.0` → `192.168.99.0/24`

`172.16.0.0/16` では、RFC の説明どおり「上位16ビットが1、下位16ビットが0」のマスクに相当し、残りのビットがサイト内のホストを表します。マスク表記との対応例として、RFC には `10.24.0.0/13` が `255.248.0.0` に対応する例があります。

## クラスフルからクラスレスへ

従来のクラス A/B/C は固定サイズでしたが、CIDR ではクラスに縛られず、2のべき乗サイズの階層的なブロックを割り当てます。RFC はクラス A/B/C による割り当て方式を非推奨としています。割り当てはプロバイダと利用者の関係に沿って行われ、経路を集約しやすくします。

RFC の表（抜粋）は次のとおりです。

```
notation       addrs/block      # blocks
n.n.n.n/32               1     4294967296    "host route"
n.n.n.0/24             256       16777216    legacy "Class C"
n.n.0.0/16           65536          65536    legacy "Class B"
n.0.0.0/8         16777216            256    legacy "Class A"
0.0.0.0/0       4294967296              1    "default route"
```

## 経路集約の例

RFC の例では、プロバイダ PA が `10.24.0.0/13`（`10.24.0.0`〜`10.31.255.255`）を受け取り、顧客へ次のように分割します。

- C1: `10.24.0.0/21`
- C2: `10.24.16.0/20`
- C3: `10.24.8.0/22`
- C4: `10.24.12.0/22`（マルチホーム、PA 経由が主）
- C5: `10.24.32.0/23`（マルチホーム、PB 経由が主）
- C6: `10.24.34.0/23`

PA はバックボーンに `10.24.12.0/22`、`10.32.0.0/20`、`10.24.0.0/13` を広告します。顧客ごとの細かい経路を個別に流さず、親ブロックにまとめられる点が集約の利点です。

## 手元で確認する

プレフィックスごとのアドレス数やネットワーク範囲は、このサイトの [サブネット計算機](/tools/subnet-calculator/) で確認できます。例えば `192.168.99.0/24` や `10.24.0.0/13` を入力して、RFC の記述と見比べてみてください。
